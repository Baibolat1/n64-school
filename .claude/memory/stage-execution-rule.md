По проекту школьного сайта (`docs/PLAN.md`) действует правило исполнения по объёму этапа:

- **S-этапы (7, 8, 10, 11) и M-этапы (9, 13, 14) — делаю сам**, без субагентов: пишу код и тесты, запускаю сайт, проверяю руками.
- **Цепочка `planner → coder → reviewer` запускается только** для этапа **12 (L)**, для **финальной проверки безопасности** и — по отдельной явной просьбе пользователя от 2026-10-13 — для **остатка этапа 13 и нового этапа 15 (аватарка)**.
- Перед запуском цепочки **показываю пользователю план** и жду «ок» — работа начинается только после этого. По плану 2026-10-13 цепочка идёт по одному этапу за раз (A, затем B), субагенты коммитов не делают.

Пользователь задал это явно (2026-10-11), вместе с порядком этапов ([[school-site-roadmap]]).

**Why:** пользователь просил не тратить токены на субагентов там, где задача посильна напрямую; цепочка нужна только для крупного L-этапа и финального аудита безопасности.

**How to apply:**
- Не запускать субагентов «на всякий случай», даже если этап выглядит крупным, — только 12 и финальный security-ревью.
- Перед цепочкой — план на утверждение; по умолчанию работаю сам, напрямую.
- Общее правило про цепочку — [[subagent-workflow]].
