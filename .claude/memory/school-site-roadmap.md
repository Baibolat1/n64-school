Решения по школьным данным и ассистенту (2026-10-13, этапы 16–20, сделано мной без цепочки):
всё школьное (расписание, ДЗ, заметки, турниры, награды) — **данные, а не код**: в базе коды
(`cs2`, `mvp`, `live`), подписи — в словарях `app/services/school.py` и
`app/services/esports.py`, тесты сверяют, что на каждый код есть подпись; `class_name` —
персональные данные, показывается только самому ученику, рядом с постами класса нет.
Демо-данные (`scripts/seed_demo.py`) выдуманы и лежат прямо в скрипте, а не в JSON, как у
учителей: настоящие имена в демонстрацию попасть не должны; идемпотентность — по естественному
ключу каждой таблицы (класс+день+урок, игра+название турнира, псевдоним); даты ДЗ и заметок
считаются от дня запуска, чтобы демонстрация не устаревала; пароль демо-аккаунта в репозитории
не лежит (выдаётся флагом `--with-login`).
Ассистент — **гибридный**: сначала ответ по базе школы, и только если база не знает **и** задан
ключ модели, вопрос уходит наружу вместе с **обезличенным** контекстом (только уроки на сегодня
и ближайшее ДЗ класса — ни псевдонима, ни класса, ни почты, ни текстов постов). Без ключа
ничего никуда не уходит. Ключ и текст вопроса не логируются, ответ помечен источником
(«база школы» / «модель» / «подсказка»). Вызов модели — сырой `httpx`, а не SDK: две разные
модели (Anthropic и DeepSeek), лишняя зависимость не нужна.

Модерация (этап 12) — фиксированные решения, чтобы не переспрашивать: **удаление мягкое и
терминальное** (`status="deleted"`, строка остаётся, `restore` возвращает только `hidden`);
**решение по объекту закрывает все его открытые жалобы** как `resolved`, а `dismiss` — ровно
одну; **бан из карточки ученика жалоб не закрывает** — это решение о человеке, а не об
объекте, и контент остаётся в ленте (бан из карточки объекта — закрывает).

Дизайн-основа подтянула за собой правку CSP: `script-src 'none'` глушил QR-сканер и поллер QR-регистрации, теперь `script-src 'self'`. Действующее правило — **любой скрипт только отдельным файлом**, инлайновый `<script>` запрещён тестом `tests/test_security_headers.py`. Редизайн в стиле «жидкого стекла» (этап 20) это правило не нарушил: ни инлайновых стилей, ни скриптов, только три CSS-файла.

Решения по аватарке (2026-10-13, этап 15, сделано): галерея **встроенная** — 12 SVG нарисованы
вручную и лежат в репозитории (`app/static/img/avatars/`), загрузки файлов нет и не планируется;
в ленте, комментариях и отзывах показывается **всегда текущая** аватарка автора (не снимок, в
отличие от псевдонима) — одним запросом на страницу; смена — свободная, без кулдауна; анонимные
записи картинку **не показывают никогда** (проверка внутри макроса `avatar` по псевдониму
«Аноним»); в админке картинка только в карточке ученика, очереди модерации текстовые. В БД —
одна колонка `students.avatar_key` (миграция `0006`), в ней только ключ из белого списка.
Валидатор `COOKIE_SECURE`/`SECRET_KEY` на старте — **только предупреждение**, не отказ старта.

Решения, закрытые пользователем вместе с порядком:

- **Статус `pending` у постов не используется.** Мягко-помеченный контент виден сразу с плейсхолдером `[скрыто]`, а модератору уходит запись в очередь `pii_flags`.
- **Данные учителей:** в git — только демо с выдуманными именами; настоящие ФИО и критерии приходят из файла вне репозитория. На этапе 9 путь закреплён по умолчанию: `data/teachers.local.json` (`TEACHERS_DATA_FILE`, маска `data/*.local.*` в `.gitignore`), заливка — `scripts/seed_teachers.py`.
- **Мат разрешён** и в постах, и в никах — словарей не добавлять, см. [[profanity-allowed]].
- **Переносы строк в постах сохраняются:** нормализация текста — только для проверки фильтром, в базу идёт оригинал с заменой совпавших фрагментов.
