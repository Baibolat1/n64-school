# Школа — закрытый сайт для учеников

Закрытый веб-сайт для учеников школы: доступ по учётным записям, контент виден только
авторизованным пользователям. Проект в разработке: работают лента с комментариями, отзывы
об учителях, жалобы и админка модерации.

## Стек

- Python 3
- FastAPI + Uvicorn
- SQLAlchemy 2.x + Alembic
- Pydantic Settings
- Jinja2 (шаблоны)

## Окружение

Создать виртуальное окружение и установить зависимости:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Скопировать пример настроек и при необходимости отредактировать:

```bash
cp .env.example .env
```

Переменные окружения (читаются из `.env`):

- `APP_NAME` — название приложения (заголовок FastAPI)
- `SECRET_KEY` — секретный ключ для подписи сессий и токенов
- `DATABASE_URL` — строка подключения к БД (по умолчанию `sqlite:///./school.db`)
- `DEBUG` — режим отладки (для локальной работы по HTTP ставьте `true`)
- `ADMIN_USERNAME` / `ADMIN_PASSWORD` — логин и пароль первого админа для `scripts/seed_admin.py`
- `COOKIE_SECURE` — включать при работе по HTTPS (cookie только по https)
- `TEACHERS_DATA_FILE` — файл с учителями и критериями для скрипта заливки
  (см. «Данные учителей и критерии»)

При старте приложение пишет **предупреждение** в лог (старт не прерывается), если
`COOKIE_SECURE=false` вне режима `DEBUG` или если `SECRET_KEY` остался дефолтным
(`change-me`). Для локальной разработки по HTTP это нормально: поставьте `DEBUG=true`.
За HTTPS задайте `COOKIE_SECURE=true` и настоящий `SECRET_KEY`.

## Данные учителей и критерии

Кто преподаёт в школе и по каким вопросам оценивают учителя — это **данные**, а не код:
форма отзыва на странице учителя строится из таблицы `criteria`. Данные заливаются скриптом:

```bash
.venv/bin/python scripts/seed_teachers.py                  # файл из TEACHERS_DATA_FILE
.venv/bin/python scripts/seed_teachers.py --file data/teachers.local.json
.venv/bin/python scripts/seed_teachers.py --prune          # отключить учителей, которых нет в файле
```

Скрипт идемпотентен: учитель сопоставляется по ФИО, критерий — по коду, поэтому повторный
запуск обновляет строки, а не плодит дубликаты. `--prune` только выключает (`is_active`),
ничего не удаляя: на учителя ссылаются отзывы.

В репозитории лежит только `data/teachers.demo.json` — демонстрационные данные с
**выдуманными** именами. Настоящие ФИО и критерии должны лежать в файле вне git
(по умолчанию `data/teachers.local.json`, маска `data/*.local.*` в `.gitignore`): ФИО
сотрудников школы — персональные данные. Если файла нет, скрипт возьмёт демо-данные и
предупредит об этом.

## Аватарка ученика

Картинку ученик выбирает на `/me` из встроенной галереи: 12 SVG лежат в репозитории
(`app/static/img/avatars/`), загрузки файлов нет. Картинка показывается рядом с псевдонимом
в ленте, на странице поста, в комментариях и в отзывах и всегда отражает текущий выбор —
старые записи тоже показывают новую картинку. Под анонимными записями картинка не
показывается: там всегда кружок с инициалом. У учителей аккаунтов нет, поэтому у них всегда
кружок. Менять выбор можно без ограничений. Форма — `POST /me/avatar`.

## Лайки и вид ленты

Пост можно отметить «нравится» — одной кнопкой-переключателем `POST /feed/posts/{id}/like`
(CSRF как у остальных форм, ответ — `303` назад на ту же страницу). Отметка одна на ученика
и пост: это гарантирует уникальный индекс `(student_id, post_id)` в таблице `post_likes`,
а не только проверка в коде, поэтому два быстрых клика не создадут вторую запись. Счётчик
лайков видят все, заполненное сердце — только тот, кто отметил. Лайков у комментариев нет,
репостов тоже.

Лента нарисована непрерывной: посты разделены тонкой линией, а не рамками, сверху
аватар-псевдоним-время, снизу — контурные иконки лайка и комментария со счётчиками.
Комментарии — в том же компактном стиле. Всё оформление и анимации (появление постов,
заливка сердца, подъём кнопок при наведении) — чистый CSS, новых библиотек и цветов нет,
инлайновых стилей и скриптов тоже (их запрещает CSP). При `prefers-reduced-motion: reduce`
движение отключается, цветовые состояния остаются.

## Админские экраны

Первый админ создаётся скриптом (логин и пароль берутся из `ADMIN_USERNAME`/`ADMIN_PASSWORD`,
если не переданы флагами):

```bash
.venv/bin/python scripts/seed_admin.py
.venv/bin/python scripts/seed_admin.py --username baibo@icloud --password '...'
```

Вход — `/admin/login`. Панель `/admin` показывает счётчики (открытые жалобы, открытые флаги
ПДн, отказы публикации, заблокированные ученики) и ведёт в разделы:

| Экран | Что там |
|---|---|
| `/admin/reports` | очередь открытых жалоб, по страницам |
| `/admin/pii` | срабатывания фильтра ПДн: правило, фрагмент, принять или отклонить |
| `/admin/blocked` | журнал отказов по жёстким правилам ПДн: ученик, правило и время — без текста |
| `/admin/audit` | журнал действий модераторов, новее сверху |
| `/admin/content/{тип}/{id}` | карточка объекта: текст, автор, жалобы, флаги, след и форма решения |
| `/admin/students/{id}` | карточка ученика: его действия, бан и разбан |
| `/admin/invites` | коды приглашений |

Модерация — **постмодерация**: контент публикуется сразу, модератор разбирает жалобы и
срабатывания фильтра. Решение по объекту — скрыть, вернуть в ленту, удалить или забанить
автора; необязательная заметка становится причиной бана. **Удаление мягкое и терминальное**:
строка остаётся в базе со статусом `deleted`, вернуть в ленту можно только скрытое. Решение по
объекту закрывает все открытые жалобы на него, отклонение жалобы — только её одну. Каждое
изменение пишется в след (`moderation_actions`), который не правится и не удаляется.

## Запуск

```bash
.venv/bin/uvicorn app.main:app --reload
```

Проверка работоспособности: `GET /health` возвращает `{"status": "ok"}`.

Сайт закрытый, поэтому он закрыт и от поисковых систем: каждый ответ уходит с заголовком
`X-Robots-Tag: noindex, nofollow`, а `GET /robots.txt` отдаёт `Disallow: /`. Тест-сканеры
только для действующих учеников (см. `/scan`), поэтому в проде сайт обязан открываться по
HTTPS.
